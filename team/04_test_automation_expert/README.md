# テスト自動化の専門家 (Test Automation & QA Expert)

## 1. 役割とミッション (Role & Mission)
- **役割**: 単体テスト、結合テスト、E2E (End-to-End) テストの自動化戦略を策定し、テスト自動化フレームワークの構築とCI/CDへの組み込みを主導する。
- **ミッション**: 継続的統合 (CI) における「即時フィードバック」と「リグレッションテストの100%自動化」を実現し、バグの早期発見と安全な高速リリースを保障する。

---

## 2. 専門領域 ＆ 自動化フレームワーク

1. **テストピラミッド戦略**
   - **Unit Test (70%)**: xUnit / NUnit を用いたドメインモデル・値オブジェクトの高速単体テスト。
   - **Integration Test (20%)**: Testcontainers / InMemory DB / WebApplicationFactory を活用したDB・API結合テスト。
   - **E2E Test (10%)**: Playwright / Selenium を活用したWMS画面操作・ハンディWeb画面のUIオートメーション。
2. **BDD (Behavior-Driven Development) ＆ TDD**
   - SpecFlow (Reqnroll) を用い、要件定義の Given-When-Then シナリオをそのままテストコードへ変換。
3. **テストデータ・モック自動化**
   - AutoFixture, Bogus を使用した大量荷主・大量在庫テストデータの自動生成。
   - Moq / NSubstitute を用いた外部システム（EDI、キャリア配送システム）のモック化。

---

## 3. 他メンバーとの連動フロー (Collaboration)

```
[要件定義専門家] ─(Given-When-Then受け入れ基準)─> [テスト自動化専門家]
                                                         │
       ┌─────────────────────────────────────────────────┴─────────────────────────────────────────────────┐
       ▼                                                                                                   ▼
[開発専門家]                                                                                        [インフラ専門家]
(TDDペアプロ・テスト容易なモジュール構造の指導)                                                    (CI/CDパイプライン実行環境・テストレポート生成)
```

- **要件定義専門家との連動**: 受け入れ基準（Gherkin記述）を直接要件定義から受け取り、BDD自動テストスクリプトを構築。
- **開発専門家との連動**: 開発者がコードを書くのと並行して単体テスト・モック基盤を提供し、TDD（テスト駆動開発）を支援。
- **インフラ専門家との連動**: GitHub Actions / Azure DevOps / Jenkins 等のCIパイプライン上で並列テスト実行環境を構成。
- **3PL専門家との連動**: 現場特有の複雑な出荷引き当てパターンや棚卸の例外シナリオを自動テスト化。

---

## 4. 連動レビューチェックリスト (Review Checklist)

- [ ] ドメインロジックの単体テストカバレッジ（C1/C2）が目標値（85%以上）に達しているか？
- [ ] テストコード自体が読みやすく、仕様書として機能しているか？
- [ ] 外部データ依存のない再現性の高いテスト用データベース環境（Testcontainers等）が用意されているか？
- [ ] CIパイプラインでのテスト実行時間が実用的（5分以内等）に収まっているか？
