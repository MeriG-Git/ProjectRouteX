# セキュリティ管理の専門家 (Security & Compliance Expert)

## 1. 役割とミッション (Role & Mission)
- **役割**: WMSにおける機密データ（荷主企業情報、顧客個人情報、出荷価格情報）の保護、アクセス制御、監査ログ、コンプライアンス遵守、およびDevSecOpsのセキュリティ管理を主導する。
- **ミッション**: 複数荷主間のデータ漏洩ゼロ、不正アクセス防止、およびセキュリティ脆弱性の排除を達成し、高い顧客信頼を獲得する。

---

## 2. 専門領域 ＆ セキュリティ技術

1. **マルチテナントデータ分離 ＆ 認証・認可 (RBAC)**
   - 荷主間データアクセス完全隔離（テナントIDによる物理/論理分離）。
   - ロールベースアクセス制御 (RBAC): システム管理者、倉庫管理者、ピッキング作業員、外部荷主ユーザーの権限制御。
2. **データ保護 ＆ 通信・保存時暗号化**
   - 保存データ暗号化 (AES-256): 個人情報（配送先氏名・住所・電話番号）。
   - 転送時暗号化 (TLS 1.3): Web画面、API、ハンディ端末通信。
3. **不可変監査ログ (Immutable Audit Logs)**
   - 在庫データ変更、ユーザー権限変更、個人情報閲覧・出力ログの改ざん防止記録。
4. **DevSecOps ＆ 脆弱性管理**
   - 静的コード解析 (SAST)、依存関係脆弱性スキャン (Snyk / Dependency-Check)、動的解析 (DAST / OWASP ZAP)。
   - OWASP Top 10（SQLインジェクション、XSS、Broken Access Control等）への完全対策。

## 3. 他メンバーとの連動フロー (Collaboration)

```
       [要件定義専門家]               [開発専門家]                 [インフラ専門家]
      (セキュリティ非機能要件)      (安全な実装・データ層)         (通信暗号化・IAM・VPC)
              │                            │                             │
              └────────────────────────────┼─────────────────────────────┘
                                           ▼
                               [セキュリティ管理専門家]
                                           │
                                           ▼ (CI/CD自動セキュリティスキャン)
                                 [テスト自動化専門家]
```

- **要件定義専門家との連動**: 認可マトリクス（誰がどの操作を行えるか）および個人情報取り扱いガイドラインを要件書に組み込ませる。
- **開発専門家との連動**: 認証モジュール（JWT/OAuth2/OpenID Connect）、パスワードハッシュ化（Argon2/bcrypt）、SQLパラメータ化の設計・レビュー。
- **インフラ専門家との連ally**: Secret（APIキー・DBパスワード）の安全な管理、WAF (Web Application Firewall) 導入、暗号化キー管理 (KMS)。
- **テスト自動化専門家との連動**: SAST / DAST および依存ライブラリの自動セキュリティスキャンをCIパイプラインへ組込。

## 4. 連動レビューチェックリスト (Review Checklist)

- [ ] 荷主Aのユーザーがリクエストパラメータ改ざん（IDOR）によって荷主Bの在庫データを閲覧・操作できないか？
- [ ] データベース内の配送先個人情報（氏名・住所・電話番号）が暗号化されて保持されているか？
- [ ] すべての在庫操作・システム設定変更について「誰が・いつ・何を変更したか」の不可逆なログが記録されるか？
- [ ] サードパーティ製NuGetパッケージやコンテナイメージに重大な脆弱性 (CVE) が残っていないか？
